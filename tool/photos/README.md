# Photo publisher

This maintainer tool publishes the static schema-1 catalog at
`https://media.countdowns.stayte.app/catalog/v1/manifest.json`.
It does not modify the Flutter app or find/download stock photos.

Install Node 22.16 or newer, then run `npm ci --prefix tool/photos`.
Commands work from any directory using the absolute path to `tool/photos/photos`.
From the repository root:

```sh
tool/photos/photos init
tool/photos/photos doctor
tool/photos/photos categories
```

## Private files and credentials

`COUNTDOWNS_MEDIA_DIR` must point outside this public repository. On this Mac the
default private location is `~/Library/Application Support/Countdowns Media`.
It contains `catalogue.yaml`, `originals/`, `evidence/`, `inbox/`, and `build/`.
The initial catalog has `enabled: false`; enable it only after reviewing content.
The live endpoint currently serves that empty, disabled version-1 manifest.

The CLI automatically loads `~/.config/countdowns-media/publisher.env` with mode
600. Use `COUNTDOWNS_PHOTOS_ENV` for another private file; variables already set
in the environment take precedence. Required settings:

- `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`: Object Read & Write on
  **countdowns-media only**, with no bucket administration permissions.
- `R2_ENDPOINT`: the account's HTTPS R2 S3 endpoint; region is `auto`.
- `CF_API_TOKEN`: Cache Purge permission for **stayte.app only**.
- `CF_ZONE_ID`: that zone's identifier.
- `COUNTDOWNS_MEDIA_DIR`: the private media directory.

The purge token has zone-level permission. The tool sends only exact media URLs
and never sends a zone-wide purge. Credentials, identifiers, original images,
license evidence, releases, and private catalog data must never be committed.

`configure_credentials.py` accepts one JSON line with the five credential fields,
hides input when run in a terminal, and creates the private environment file with
mode 600. It refuses to replace an existing file. Never paste credentials into
shell commands, a tracked file, or chat. Rotate/revoke these tokens in Cloudflare
if this machine or the credential file is compromised.

```sh
python3 tool/photos/configure_credentials.py
tool/photos/photos doctor --remote
# Explicit temporary upload, read-back, deletion, and exact-URL purge test:
tool/photos/photos doctor --upload-test
```

## Add and review photos

Only `CC0-1.0`, `PDM-1.0`, `owned`, and `commissioned` are accepted. Check the
individual source's redistribution rights and any necessary releases before
adding it. Every license except `owned` requires a saved evidence file.

```sh
tool/photos/photos add /private/path/photo.jpg \
  --categories christmas,winter --license CC0-1.0 \
  --evidence /private/path/license.pdf \
  --credit-name 'Photographer' --credit-url https://example.com/photographer \
  --page https://example.com/photo --tags tree,lights,snow
tool/photos/photos build
```

Review `build/contact-sheet.html` in the private directory and edit the private
`catalogue.yaml` for categories, tags, credits, `focal: {x: 0.5, y: 0.35}`,
`hidden: true`, category covers, or `enabled: true`. Category IDs are read directly
from the app's existing category file; `photos categories` exports their JSON list.
The tool never edits that app file.

Build applies EXIF orientation, converts to sRGB, flattens transparency onto white,
and strips embedded metadata, including EXIF/GPS and ICC metadata. It generates:

- A WebP thumbnail, at most 480 px on the long edge, quality 70.
- A progressive JPEG, at most 2560 px on the long edge, quality 82.
- The full variant's actual `w` and `h`, a thumbnail average `color`, and a
  **4×3 BlurHash** encoded from a small RGBA thumbnail. The public photo entry uses
  the lowercase **`blurhash`** field already supported by the app.

No upscaling is performed. Smaller sources require `add --allow-small` (stored as
`allowSmall: true` in the private catalog). File sizes vary with image detail;
the plan's size targets are estimates, not quality-destroying hard limits.
Only explicitly selected public fields reach the manifest. The output cache checks
original content, processor settings, and generated bytes before reusing files.

## Publish and recover

```sh
tool/photos/photos publish --dry-run
tool/photos/photos publish
tool/photos/photos rollback 3 --dry-run
tool/photos/photos rollback 3
tool/photos/photos purge
```

Dry run makes **no remote changes**. Without credentials it reports an offline
plan. With credentials it checks existing files and computes the next version.
Build output may be refreshed in the private directory during either dry run.

Publish builds current inputs, verifies existing immutable objects, uploads new
variants, reserves a new immutable `manifest-N.json`, then conditionally replaces
the live manifest and purges that one URL. Images and snapshots use
`public, max-age=31536000, immutable`; the live manifest uses
`public, max-age=300`. A local lock and conditional S3 writes prevent silent
overwrites by concurrent publishers. Reserved snapshots survive failures and
their version numbers are never reused, including after rollback.

Rollback checks that the chosen snapshot and referenced images exist, conditionally
replaces the live manifest, and purges it. It does not delete snapshots or photos.
If a cache purge fails after an upload or rollback succeeds, run `photos purge`;
the error explicitly reports that the live manifest already changed.

An interrupted process can leave `.publish.lock` in the private media directory.
Confirm no publisher is still running before removing that local lock. Originals
are never uploaded. Old published image keys are retained for existing users.

## Verification

Run `npm test --prefix tool/photos`. Tests cover orientation, metadata removal,
BlurHash decoding, private-data exclusion, evidence and category validation,
no-upscaling, output reuse/corruption, publication order, dry runs, concurrent
updates, failed purges, and rollback/version preservation. CI runs these checks
for publisher changes targeting `dev`.

Cloudflare delivery is configured only for `media.countdowns.stayte.app` and its
`/catalog/` and `/p/` paths. HTTP redirects to HTTPS. Origin cache headers are
respected, errors bypass the cache, `r2.dev` is disabled, and Smart Tiered Cache
remains off. The existing $10 account-wide budget alert includes R2 but is not a
hard spending cap. There is no hostname-scoped rate-limit rule on the current
Free plan.
